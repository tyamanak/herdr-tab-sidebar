# 使い方

[English](usage.md) | 日本語

このページは、herdr-tab-sidebar の [README](../README.ja.md) の続きです。

## 動作要件

- Herdr 0.9.1 以降。開発とテストには Herdr 0.9.3 を使用しました。
- Python 3.9 以降。Herdr サーバーの PATH 上で `python3` として見つかる必要があります。使用するのは標準ライブラリのみです。`python3` がそれより古い場合は、すべてのフックとアクションがその旨のメッセージを出して失敗します。
- macOS または Linux。以下の内容はすべて macOS で実行したものです。Linux では、まだ何も手で試していません。ユニットテストは、CI 上で Linux でも実行するように設定してあります。

## インストールは1つだけ

インストールは 1 つだけにしてください。別のプラグイン ID で 2 つ目をインストールすると（フォークや、インストール済みのものと並べてローカルでクローンを `herdr plugin link` した場合）、同じ `ts_*` トークンと `config.toml` の同じ管理ブロックを書き込むことになり、互いの結果を打ち消し合います。

## 確認

```sh
herdr plugin action invoke tyamanak.tab-sidebar.status
herdr plugin log list --plugin tyamanak.tab-sidebar
```

`status` アクションの最終出力行は、`state: applied` や `state: released`、またはそのどちらかになるのを妨げている原因です。アクションはバックグラウンドで動作するため、出力やエラーは呼び出した端末ではなくプラグインログに残ります。

このリポジトリのクローンからは、終了コードを返す 1 つのコマンドで同じ確認を行えます。

```sh
python3 main.py status --expect applied    # or: --expect released
```

`OK: applied (N rows)` か、`NOT applied:` とその理由を出力します。`python3 main.py preview` は、現在のセッションから生成される行を出力します。どちらも読み取りのみを行います。

## アクション

| アクション | 効果 |
|---|---|
| `tyamanak.tab-sidebar.apply` | 管理ブロックを `config.toml` に追加して設定を再読み込みし、ビューを設定してすべてのトークンを書き込む |
| `tyamanak.tab-sidebar.release` | ビューとすべてのトークンを削除し、管理ブロックを取り除いて設定を再読み込みする |
| `tyamanak.tab-sidebar.resync` | 現在のセッションをもとに、ビューとすべてのトークンを書き直す |
| `tyamanak.tab-sidebar.status` | 状態を報告する。何も変更しない |

一覧はセッションの変化に自動で追従し（ワークスペースの名前変更、タブの作成・クローズ・名前変更・移動、ペインのクローズ・移動、エージェントの検出とその状態の変化）、サーバーの再起動後も復元されます。`resync` は、それでも一覧が古いままに見える場合に使います。

## 更新

更新するには、再度インストールします。Herdr がチェックアウトを置き換えます。

```sh
herdr plugin install tyamanak/herdr-tab-sidebar
```

## 制限

- シェルなど、エージェントのいないタブは一覧に表示されません。Herdr が一覧に表示するのは、エージェントが動いているペインのみです。
- 状態アイコンは行の先頭ではなく末尾にあります。Herdr は各項目の 1 行目とそれに続く行でインデントを変えるため、アイコンを先頭に置くと、ワークスペースの最初のタブとそれ以外のタブで位置が揃いません。
- 適用中は、プラグインの一覧が Herdr 自身の Agents パネルの並び順（`agent_panel_sort`）に取って代わります。`release` で元に戻ります。
- Herdr の Agent ビューは 1 つだけです。プラグインの実行ごとにこのビューを設定するため、ビューを設定する他のプラグインとは互いのビューを上書きし合います。そのようなプラグインとの併用は試していません。
- 別のマシンのエージェント（Herdr は 1 つのクライアントに複数のマシンを表示できます）は、ローカルのグループの後ろに行が残りますが、表示されるのはマシン名と状態アイコンのみです。行レイアウトの定義は全行共通で、プラグインのトークンはローカルのペインにしか存在しないためです。これはコードとユニットテスト上での話で、実際のリモート接続では確かめていません。そうした使い方が中心であれば、事前に `release` しておいてください。
- 複数のエージェントがいるタブでは、プラグインの適用中、次/前のエージェントへの移動で他のエージェントにたどり着けません。
- Herdr が同時に実行するプラグインのコマンドは最大 32 個で、超過分は破棄されます。一度に大量の変更が発生して一覧が古いままになった場合は、次の変更か `resync` で直ります。
- 試していないこと: セッションを動かしたまま Herdr をその場で更新すること。単純なサーバーの再起動は、テストで確かめています（起動時フックが一覧を復元します）。
