## 変更する内容

**`config.toml`。** `apply` は Herdr の `config.toml` の末尾に次の 8 行を追記し、ファイルの他の部分には一切触れません。`release` はその 8 行を削除し、ファイルをバイト単位で元に戻します。

```toml
# >>> herdr-tab-sidebar: managed block, remove with the plugin's release action >>>
[ui.sidebar.agents]
row_gap = 0
rows = [
  [{ token = "$ts_group", bold = true }],
  ["$ts_label", "$ts_extra", { token = "machine", rules = [{ equals = "Local", hide = true }] }, "state_icon"],
]
# <<< herdr-tab-sidebar <<<
```

- 新しいファイルは、古いファイルと置き換える前に `herdr config check` で検査します。変更前のファイルは、プラグインの状態ディレクトリ（`~/.local/state/herdr/plugins/tyamanak.tab-sidebar/backups/`、または `$XDG_STATE_HOME` の下）にコピーを残します。変更ごとにコピーが追加され、既存のコピーが上書きされることはありません。
- `config.toml` がすでに何らかの形で `[ui.sidebar.agents]` を定義している場合、`apply` は拒否して何も変更しません。2 つのレイアウトを同時に有効にはできないため、既存の定義を削除またはコメントアウトしてから `apply` を実行してください。自分の定義の一部を戻したい場合（2 行目に独自のトークンを入れたい場合など）は、管理ブロック内の行を編集します。その編集内容は次の `apply` まで保持され、その際に管理ブロックは初期状態に戻ります。`release` は管理ブロックを完全に削除します。
- `config.toml` がシンボリックリンクの場合（dotfiles リポジトリなど）、リンク先のファイルを書き換え、リンク自体は維持します。ファイルに書き込めない場合（読み取り専用のストアなど）、`apply` は失敗し、何も変更しません。
- `apply` や `release` の処理中に `config.toml` が変更された場合（エディターでの保存や別のツールなど）、書き込みは行わずにその旨を通知します。再度実行してください。
- 2 つのマーカー行は、そのままにしておく必要があります。それぞれが単独の行にあり、1 つずつで、開始の行が先です。どちらかが欠けたり、重複したり、移動したりしていると、`apply` も `release` も拒否して何も変更せず、`status` はマーカーが壊れていると報告します。直し方は[手作業で取り除く](#手作業で取り除く)にあります。
- 初回の `apply` で後のほうの手順が失敗した場合は、それまでに書き込んだ管理ブロック・ビュー・トークンを取り消そうとし、失敗を報告します。すべてを取り消せなかった場合（たとえば Herdr が応答しなくなったとき）は、残っているものをエラーが示します。`status` で状態を確認でき、残りを取り除く方法は[手作業で取り除く](#手作業で取り除く)にあります。

**Agents パネル。** 適用中はプラグインが Herdr の Agent ビューを管理し（パネルのヘッダーに `tabs` と表示されます）、エージェントのペインに `ts_*` という表示専用トークンを 6 つ書き込みます。セッションの他の部分は変更しません。また、プラグインは `apply` の前や `release` の後には何もしません。

## 解除が終わらないとき

[アンインストール](../README.ja.md#アンインストール)の手順 2 では、最新の `status` のエントリーが `state: released` で終わるのを待ちます。

`release` のエントリーが失敗している場合は、エラー内容を確認して原因を解消し、再度解除を実行してください。管理ブロックの削除後、Herdr が `config.toml` を再読み込みするまで、`status` は `released` と報告しません。再度解除を実行すると、再読み込みをやり直します。

まれに、そのような再読み込みの失敗後に `apply` が失敗すると、画面に古いレイアウトが残ったまま（Agents パネルの全行に状態アイコンのみ表示される）、`status` が `released` と報告することがあります。その場合は `herdr server reload-config` を実行して、Herdr のメモリー上の設定を更新してください。

## 手作業で取り除く

`release` で正常に戻せない場合の手順です。プラグインを先にアンインストールした、マーカーが破損している、`apply` 失敗時の取り消しが完了しなかった場合などが該当します。

1. `config.toml` からプラグインの行を削除します。`# >>> herdr-tab-sidebar` から `# <<< herdr-tab-sidebar <<<` まで、両方のマーカーを含めて削除してください。マーカーが欠落または重複している場合は、すべてのマーカー行と、[変更する内容](#変更する内容)に示した `[ui.sidebar.agents]` テーブルを削除し、自身で書いた行は残します。
2. `herdr server reload-config` を実行します。実行するまでは、Agents パネルのどの行にも状態アイコンしか表示されないことがあります。
3. プラグインがまだインストールされている場合は、もう一度 `release` を実行してビューとプラグインのフラグを破棄し、`status` で確認します。

ペインに残った `ts_*` トークンは表示専用であり、管理ブロックがなくなれば描画されることはありません。
