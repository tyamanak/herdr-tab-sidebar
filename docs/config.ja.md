## 変更する内容

**`config.toml`。** `apply` は、Herdr の `config.toml` の末尾に次の 8 行を追記し、ファイルのほかの部分には一切触れません。`release` はその 8 行を取り除き、ファイルをバイト単位で元どおりに戻します。

```toml
# >>> herdr-tab-sidebar: managed block, remove with the plugin's release action >>>
[ui.sidebar.agents]
row_gap = 0
rows = [
  [{ token = "$ts_group", bold = true }],
  ["$ts_label", "$ts_extra", { token = "machine", rules = [{ equals = "Local", hide = true }] }, "state_icon"],
]
# <<< herdr-tab-sidebar <<<
```

- 新しいファイルは、古いファイルと置き換える前に `herdr config check` で検査します。古いファイルのコピーは、プラグインの状態ディレクトリ（`~/.local/state/herdr/plugins/tyamanak.tab-sidebar/backups/`、または `$XDG_STATE_HOME` の下）に残します。変更のたびにコピーが 1 つ増え、上書きされるものはありません。
- `config.toml` がすでに何らかの形で `[ui.sidebar.agents]` を定義している場合、`apply` は拒否して何も変更しません。2 つのレイアウトを同時に有効にはできないので、自分の定義を削除するかコメントアウトしてから `apply` を実行してください。自分の定義の一部を戻したいとき（たとえば 2 行目に自分のトークンを入れたいとき）は、管理ブロックの中の行を編集します。その編集は次の `apply` まで残り、そのときに管理ブロックは初期状態に戻ります。`release` は管理ブロックを丸ごと取り除きます。
- `config.toml` がシンボリックリンクの場合（たとえば dotfiles のリポジトリ）、リンク先のファイルを書き換え、リンクはそのまま残します。ファイルに書き込めない場合（読み取り専用のストア）、`apply` は失敗し、何も変更しません。
- `apply` や `release` が処理している最中に `config.toml` が変わった場合（エディターでの保存や別のツール）、アクションは何も書き込まず、その旨を伝えます。もう一度実行してください。
- 2 つのマーカー行は、そのままにしておく必要があります。それぞれが単独の行にあり、1 つずつで、開始の行が先です。どちらかが欠けたり、重複したり、移動したりしていると、`apply` も `release` も拒否して何も変更せず、`status` はマーカーが壊れていると報告します。直し方は[手作業で取り除く](#手作業で取り除く)にあります。
- 初回の `apply` で後のほうの手順が失敗した場合は、それまでに書き込んだ管理ブロック・ビュー・トークンを取り消そうとし、失敗を報告します。すべてを取り消せなかった場合（たとえば Herdr が応答しなくなったとき）は、残っているものをエラーが示します。`status` で状態を確認でき、残りを取り除く方法は[手作業で取り除く](#手作業で取り除く)にあります。

**Agents パネル。** 適用中は、プラグインが Herdr の Agent ビューを受け持ち（パネルのヘッダーに `tabs` と表示されます）、エージェントのペインに `ts_*` という名前の表示専用のトークンを 6 つ書き込みます。セッションのそれ以外の部分は変更しません。プラグインは `apply` の前には何もせず、`release` の後にも何もしません。

## 解除が終わらないとき

[アンインストール](../README.ja.md#アンインストール)の手順 2 では、最新の `status` のエントリーが `state: released` で終わるのを待ちます。

`release` のエントリーが失敗していた場合は、そのエラーに理由が書かれています。それを直して、もう一度解除してください。管理ブロックを取り除いたあと、Herdr が `config.toml` を再読み込みしていない間は、`status` は `released` と報告しません。もう一度解除すると、再読み込みをやり直します。

まれに、そのように再読み込みが失敗したあとで `apply` が失敗すると、古いレイアウトが画面に残ったまま（Agents パネルのどの行にも状態アイコンしか表示されない）、`status` が `released` と報告することがあります。その場合は `herdr server reload-config` を実行して、Herdr がメモリー上に持っている設定を更新してください。

## 手作業で取り除く

`release` では片付けられない場合のための手順です。プラグインを先にアンインストールしてしまった、マーカーが壊れている、失敗した `apply` がすべてを取り消せなかった、といった場合です。

1. `config.toml` で、プラグインの行を削除します。`# >>> herdr-tab-sidebar` のマーカーから `# <<< herdr-tab-sidebar <<<` のマーカーまでで、両方のマーカーを含みます。マーカーが欠けているか重複している場合は、マーカーの行をすべてと、[変更する内容](#変更する内容)に示した `[ui.sidebar.agents]` のテーブルを削除し、自分で書いた行は残します。
2. `herdr server reload-config` を実行します。それまでは、Agents パネルのどの行にも状態アイコンしか表示されないことがあります。
3. プラグインがまだインストールされている場合は、もう一度 `release` を実行して、ビューとプラグインのフラグを捨てさせ、`status` で確認します。

ペインに残った `ts_*` トークンは表示専用で、管理ブロックがなくなれば、それを描画するものはありません。
