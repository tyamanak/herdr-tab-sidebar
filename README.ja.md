# herdr-tab-sidebar

[English](README.md) | 日本語

サイドバーの Agents パネルを縦型のタブ一覧に変える [Herdr](https://herdr.dev) プラグインです。エージェントのいるタブを 1 つにつき 1 行で表示し、ワークスペースごとの見出しの下にまとめます。

![エージェントのタブをワークスペースごとにまとめて表示した Agents パネル](docs/demo.svg)

この画像は、`demo/run.py --svg` で描いた架空のセッションです。[デモ](#デモ)を参照してください。

- ワークスペースは Spaces パネルの順（自分で並べた順）に、タブはタブバーの順に並びます。
- 複数のエージェントがいるタブも 1 行です。`+1` は自分の行を持たないエージェントの数で、その後ろの `!` は、そのうちのどれかが blocked か done の状態であることを表します。
- 行を選択すると、そのタブの代表ペインにフォーカスが移ります。
- エージェントのいないタブは一覧に出ません。Herdr が一覧に出すのはエージェントが動いているペインだけなので、シェルしかないタブには行がありません。

## 動作要件

- Herdr 0.9.1 以降。開発とテストには Herdr 0.9.3 を使いました。
- Python 3.9 以降。Herdr サーバーの PATH 上で `python3` として見つかる必要があります。使うのは標準ライブラリだけです。`python3` がそれより古い場合は、すべてのフックとアクションが、その旨のメッセージを出して失敗します。
- macOS または Linux。以下の内容はすべて macOS で実行したものです。Linux では、まだ何も手で試していません。ユニットテストは、CI で Linux 上でも実行するように設定してあります。

## インストール

```sh
herdr plugin install tyamanak/herdr-tab-sidebar
herdr plugin action invoke tyamanak.tab-sidebar.apply
```

インストールしただけでは、目に見える変化はありません。`apply` が行のレイアウトを `config.toml` に追加し（[変更する内容](#変更する内容)を参照）、設定を再読み込みして、行の中身を埋めます。

インストールは 1 つだけにしてください。別のプラグイン ID で 2 つ目を入れると（フォークや、インストール済みのものと並べてクローンをローカルで `herdr plugin link` した場合）、同じ `ts_*` トークンと、`config.toml` の同じ管理ブロックを書き込むことになり、互いの結果を打ち消し合います。

### 確認

```sh
herdr plugin action invoke tyamanak.tab-sidebar.status
herdr plugin log list --plugin tyamanak.tab-sidebar
```

`status` アクションが最後に出力した行は、`state: applied` か `state: released`、またはそのどちらかになるのを妨げているものです。アクションはバックグラウンドで動くので、その出力やエラーは、呼び出した端末ではなくプラグインログに残ります。

このリポジトリのクローンからは、同じ確認を、終了コードを返す 1 つのコマンドで行えます。

```sh
python3 main.py status --expect applied    # or: --expect released
```

`OK: applied (N rows)` か、`NOT applied:` とその理由を出力します。`python3 main.py preview` は、現在のセッションから作られる行を出力します。どちらも読み取りしか行いません。

### その他のアクション

| アクション | 効果 |
|---|---|
| `tyamanak.tab-sidebar.apply` | 管理ブロックを `config.toml` に追加し、設定を再読み込みし、ビューを設定して、すべてのトークンを書き込む |
| `tyamanak.tab-sidebar.release` | ビューとすべてのトークンを消し、管理ブロックを取り除いて、設定を再読み込みする |
| `tyamanak.tab-sidebar.resync` | 現在のセッションをもとに、ビューとすべてのトークンを書き直す |
| `tyamanak.tab-sidebar.status` | 状態を報告する。何も変更しない |

一覧はセッションの変化にひとりでに追従し（ワークスペースの名前変更、タブの作成・クローズ・名前変更・移動、ペインのクローズ・移動、エージェントの検出とその状態の変化）、サーバーを再起動したあとも復元されます。`resync` は、それでも一覧が古いままに見えるときのためのものです。

更新するには、もう一度インストールします。Herdr がチェックアウトを置き換えます。

```sh
herdr plugin install tyamanak/herdr-tab-sidebar
```

## 変更する内容

**`config.toml`。** `apply` は、Herdr の `config.toml` の末尾に次の 8 行を追記し、ファイルのほかの部分には一切触れません。`release` はその 8 行を取り除き、ファイルをバイト単位で元どおりに戻します。

```toml
# >>> herdr-tab-sidebar: managed block, remove with the plugin's release action >>>
[ui.sidebar.agents]
row_gap = 0
rows = [
  [{ token = "$ts_group", bold = true }],
  ["$ts_label", "$ts_extra", { token = "machine", rules = [{ equals = "Local", hide = true }] }, "state_icon"],
]
# <<< herdr-tab-sidebar <<<
```

- 新しいファイルは、古いファイルと置き換える前に `herdr config check` で検査します。古いファイルのコピーは、プラグインの状態ディレクトリ（`~/.local/state/herdr/plugins/tyamanak.tab-sidebar/backups/`、または `$XDG_STATE_HOME` の下）に残します。変更のたびにコピーが 1 つ増え、上書きされるものはありません。
- `config.toml` がすでに何らかの形で `[ui.sidebar.agents]` を定義している場合、`apply` は拒否して何も変更しません。2 つのレイアウトを同時に有効にはできないので、自分の定義を削除するかコメントアウトしてから `apply` を実行してください。自分の定義の一部を戻したいとき（たとえば 2 行目に自分のトークンを入れたいとき）は、管理ブロックの中の行を編集します。その編集は次の `apply` まで残り、そのときに管理ブロックは初期状態に戻ります。`release` は管理ブロックを丸ごと取り除きます。
- `config.toml` がシンボリックリンクの場合（たとえば dotfiles のリポジトリ）、リンク先のファイルを書き換え、リンクはそのまま残します。ファイルに書き込めない場合（読み取り専用のストア）、`apply` は失敗し、何も変更しません。
- `apply` や `release` が処理している最中に `config.toml` が変わった場合（エディターでの保存や別のツール）、アクションは何も書き込まず、その旨を伝えます。もう一度実行してください。
- 2 つのマーカー行は、そのままにしておく必要があります。それぞれが単独の行にあり、1 つずつで、開始の行が先です。どちらかが欠けたり、重複したり、移動したりしていると、`apply` も `release` も拒否して何も変更せず、`status` はマーカーが壊れていると報告します。手作業での直し方は[アンインストール](#アンインストール)にあります。
- 初回の `apply` で後のほうの手順が失敗した場合は、それまでに書き込んだ管理ブロック・ビュー・トークンを取り消そうとし、失敗を報告します。すべてを取り消せなかった場合（たとえば Herdr が応答しなくなったとき）は、残っているものをエラーが示します。`status` で状態を確認でき、残りを手作業で取り除く方法は[アンインストール](#アンインストール)にあります。

**Agents パネル。** 適用中は、プラグインが Herdr の Agent ビューを受け持ち（パネルのヘッダーに `tabs` と表示されます）、エージェントのペインに `ts_*` という名前の表示専用のトークンを 6 つ書き込みます。セッションのそれ以外の部分は変更しません。プラグインは `apply` の前には何もせず、`release` の後にも何もしません。

## 制限

- エージェントのいないタブには行がありません（このページの冒頭を参照）。
- 状態アイコンは、行の先頭ではなく末尾にあります。Herdr は 1 つの項目の最初の行と、それに続く行とでインデントを変えるので、アイコンを先頭に置くと、ワークスペースの最初のタブとそれ以外のタブとで位置がそろいません。
- 適用中は、プラグインの一覧が、Herdr 自身による Agents パネルの並び順（`agent_panel_sort`）に取って代わります。`release` で元に戻ります。
- Herdr の Agent ビューは 1 つだけです。プラグインは実行のたびにこれを設定するので、別のプラグインが設定したビューを置き換えます。逆に、ビューを設定する別のプラグインは、このプラグインのビューを置き換えます。そのようなプラグインとの併用は試していません。
- 別のマシンのエージェント（Herdr は 1 つのクライアントに複数のマシンを表示できます）は、ローカルのグループの後ろに行が残りますが、その行に表示されるのはマシン名と状態アイコンだけです。行のレイアウトはすべての行に共通の 1 つの定義で、プラグインのトークンはローカルのペインにしか存在しないためです。これはコードとユニットテストの上での話で、実際のリモート接続では確かめていません。そのような使い方がほとんどであれば、先に `release` しておいてください。
- 複数のエージェントがいるタブのほかのエージェントには、プラグインの適用中、次/前のエージェントへの移動ではたどり着けません。
- Herdr が同時に実行するプラグインのコマンドは最大 32 個で、それを超えた分は捨てられます。非常に大きな変更が一度に起きて一覧が古いままになった場合は、次の変更か `resync` で直ります。
- 試していないこと: セッションを動かしたまま Herdr をその場で更新すること。単純なサーバーの再起動は、テストで確かめています（起動時フックが一覧を復元します）。

## アンインストール

まず解除し、解除を確認できてからアンインストールしてください。アクションはバックグラウンドで動き、`invoke` はアクションが終わる前に戻ります。そのため、以下は 3 つの別々の手順であり、まとめて貼り付ける 1 つのブロックではありません。

1. 解除します。

   ```sh
   herdr plugin action invoke tyamanak.tab-sidebar.release
   ```

2. 状態を問い合わせ、少し待ってから、ログで答えを読みます。

   ```sh
   herdr plugin action invoke tyamanak.tab-sidebar.status
   ```

   ```sh
   herdr plugin log list --plugin tyamanak.tab-sidebar
   ```

   最新の `status` のエントリーが `state: released` で終わっていれば、次へ進みます。`release` のエントリーが失敗していた場合は、そのエラーに理由が書かれています。それを直して、もう一度解除してください。管理ブロックを取り除いたあと、Herdr が `config.toml` を再読み込みしていない間は、`status` は `released` と報告しません。もう一度解除すると、再読み込みをやり直します。

   まれに、そのように再読み込みが失敗したあとで `apply` が失敗すると、古いレイアウトが画面に残ったまま（Agents パネルのどの行にも状態アイコンしか表示されない）、`status` が `released` と報告することがあります。その場合は `herdr server reload-config` を実行して、Herdr がメモリー上に持っている設定を更新してください。

3. アンインストールします。

   ```sh
   herdr plugin uninstall tyamanak.tab-sidebar
   ```

### 手作業で取り除く

`release` では片付けられない場合のための手順です。プラグインを先にアンインストールしてしまった、マーカーが壊れている、失敗した `apply` がすべてを取り消せなかった、といった場合です。

1. `config.toml` で、プラグインの行を削除します。`# >>> herdr-tab-sidebar` のマーカーから `# <<< herdr-tab-sidebar <<<` のマーカーまでで、両方のマーカーを含みます。マーカーが欠けているか重複している場合は、マーカーの行をすべてと、[変更する内容](#変更する内容)に示した `[ui.sidebar.agents]` のテーブルを削除し、自分で書いた行は残します。
2. `herdr server reload-config` を実行します。それまでは、Agents パネルのどの行にも状態アイコンしか表示されないことがあります。
3. プラグインがまだインストールされている場合は、もう一度 `release` を実行して、ビューとプラグインのフラグを捨てさせ、`status` で確認します。

ペインに残った `ts_*` トークンは表示専用で、管理ブロックがなくなれば、それを描画するものはありません。

## 仕組み

`main.py` は短いプログラムで、Herdr がマニフェストの起動時フック・イベントフック・アクションから起動します。実行のたびに `session.snapshot` を読み、各ペインが持つべきトークンを計算して（`tab_sidebar/plan.py`）、差分だけを `pane.report_metadata` で書き込みます。常駐するものはありません。

| トークン | 付く先 | 意味 |
|---|---|---|
| `ts_m` | 一覧に出るタブの、すべてのエージェントのペイン | このプラグインが扱っている |
| `ts_rep` | タブの代表ペイン | このペインがタブの行になる |
| `ts_pos` | 代表ペイン | タブバーでの位置（ゼロ埋め） |
| `ts_group` | ワークスペースの最初の代表ペイン | 見出しの文字列 |
| `ts_label` | 代表ペイン | タブ名 |
| `ts_extra` | 代表ペイン | ほかのエージェントの数 `+N`。対応が必要なものがあれば `!` |

`agent.view.set`（source は `plugin:tyamanak.tab-sidebar`、label は `tabs`）は、代表ペインと、プラグインが印を付けていないペインを残し、`ts_m`、Herdr 自身の `workspace_order`、`ts_pos` の順で並べ替えます。ワークスペースの順序は Herdr のものなので、ワークスペースを並べ替えても、フックもトークンの変更も必要ありません。

実行は、プラグインの状態ディレクトリの下のロックで直列化しています。待っている間に、先の実行がそのイベントの分まで済ませていた場合、その実行は何もせずに終了します。ロックを持っている実行は、新しいスナップショットに変更が要らなくなるまで繰り返します（最長 8 秒。それを過ぎると、後続の実行が待っていない限り失敗します）。

## テスト

```sh
python3 -m unittest discover -s tests -t .
python3 tests/isolated/run.py
```

1 つ目のコマンドに必要なのは Python だけです。2 つ目には、PATH 上の `herdr`（または `--herdr PATH`）が必要です。一時ディレクトリの下に専用のヘッドレスの Herdr サーバー（設定・状態・プラグインのレジストリ・ソケット）を起動し、このチェックアウトをそこにリンクして、実際のフック・アクション・描画を動かします。そのサーバーの環境は一から組み立て、接続したサーバーが一時ディレクトリの中のソケットを報告しない限り先へ進まず、最後にそのディレクトリを削除します。自分のセッションと `~/.config/herdr` には触れません。

## デモ

```sh
python3 demo/run.py              # open the demo session in this terminal
python3 demo/run.py --text       # print the screen as text
python3 demo/run.py --svg FILE   # write the screen as an SVG image
```

デモは、テストと同じ種類の使い捨てのサーバーを使い、そこに架空のワークスペースとタブを入れます。エージェントは起動しません。ペインは用意したテキストを表示し、その状態は `herdr pane report-agent` で報告します。1 つ目の形式は、開く前に終了の方法（`ctrl+g`、続けて `q`）を伝え、終了したとき、または端末を閉じたときに、サーバーとそのディレクトリを削除します。Herdr の中から起動していて、自分のプレフィックスキーが `ctrl+g` の場合は、`--prefix` で別のキーを渡してください。
